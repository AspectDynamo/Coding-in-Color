# API reference

Base path: `/api/v1`, same origin as the SPA. JSON in and out.

Sources: endpoint list and DTOs in `src/shared/api.ts` (`ENDPOINTS`), body schemas in `src/shared/validation.ts`, handlers in `src/backend/routes/*.ts`, permissions in `src/shared/constants.ts` (`ROLE_PERMISSIONS`). If this page and the code disagree, the code wins.

## Conventions

**Success.** `{ "data": <DTO> }`. Lists that are paged return `{ "data": [...], "page": { "limit", "offset", "total" } }`. Lists that are not paged return a bare array in `data`.

**Errors.** Every error uses one envelope:

```json
{
  "error": {
    "code": "invalid_code",
    "message": "That code didn't work. Check it and try again.",
    "details": []
  }
}
```

`details` is present only for some errors. Validation errors (`bad_request`) list field paths and zod issue codes. They never echo submitted values.

| Code               | HTTP status                      | Meaning                                                                                             |
| ------------------ | -------------------------------- | --------------------------------------------------------------------------------------------------- |
| `bad_request`      | 400                              | Validation failed, or a business rule rejected the input. `details` gives the field paths.          |
| `unauthenticated`  | 401                              | No valid session, or the session has been revoked, withdrawn or disabled.                           |
| `invalid_code`     | 401                              | Student code unknown, revoked, withdrawn or malformed. All four give the same response.             |
| `mfa_required`     | 401                              | Wrong or unusable TOTP code during MFA verification.                                                |
| `forbidden`        | 403                              | Role lacks the permission, or the resource is outside the caller's program scope.                   |
| `csrf_failed`      | 403                              | Missing or mismatched CSRF token, or a bad `Origin`.                                                |
| `consent_required` | 403                              | Student is `pending_consent`. Assessment routes refuse them.                                        |
| `not_found`        | 404                              | Unknown resource, or a resource the caller may not see (for example a student who is not enrolled). |
| `conflict`         | 409                              | Already submitted, or a state conflict.                                                             |
| `session_closed`   | 409                              | The assessment session is not open now.                                                             |
| `rate_limited`     | 429                              | Too many attempts. The response sets `Retry-After: 60`.                                             |
| `ai_unavailable`   | 503                              | Workers AI failed or is not bound. `details.fallback` holds a template report.                      |
| `not_configured`   | 503                              | Secrets or the data store are not set. Every route except `/health` and `/config` returns this.     |
| `internal`         | 500, or 503 for the auth service | Unexpected failure. Messages are generic on purpose.                                                |

**Headers.** Every API response sends `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `X-Frame-Options: DENY` and `X-Request-Id`. Send an `X-Request-Id` (8 to 64 characters from `A-Za-z0-9._-`) to correlate logs, or one is generated.

**Unrecognised routes** return `404 not_found`.

## Authentication and CSRF

Three cookies carry state. Nothing auth-related is stored in browser storage.

| Cookie        | Set by                                                                                       | Flags                                                    | Lifetime              |
| ------------- | -------------------------------------------------------------------------------------------- | -------------------------------------------------------- | --------------------- |
| `cic_student` | `POST /student/session`                                                                      | HttpOnly, SameSite=Lax, Path=/, Secure outside localhost | 4 hours               |
| `cic_staff`   | `POST /auth/login` (after MFA if required), `POST /auth/mfa/verify`, `POST /auth/demo-login` | HttpOnly, SameSite=Lax, Path=/, Secure outside localhost | 8 hours               |
| `cic_mfa`     | `POST /auth/login` when MFA is required or enrollment is required                            | HttpOnly, SameSite=Lax                                   | 5 minutes, single use |
| `cic_csrf`    | Any request that lacks it (readable by JavaScript)                                           | SameSite=Lax, Path=/                                     | Until cleared         |

Sessions are re-checked on every request. A withdrawn student, a revoked credential, or a disabled or role-changed staff member loses access immediately.

**CSRF.** Every `POST`, `PUT`, `PATCH` and `DELETE` must send:

1. An `X-CSRF-Token` header equal to the `cic_csrf` cookie (compared in constant time), and
2. An `Origin` header equal to the request origin or listed in `ALLOWED_ORIGINS`. If `Origin` is absent, `Sec-Fetch-Site` must be `same-origin`.

If the cookie is missing, the request fails even when the header is present. **Bootstrap:** make one `GET` request first, for example `GET /api/v1/config`. It sets `cic_csrf`. Then copy the cookie's value into the header. See [troubleshooting](troubleshooting.md#csrf-403-on-every-post).

**Staff routes.** Every `/admin/*` and `/instructor/*` route requires a valid `cic_staff` cookie (`401` otherwise), then checks the permission listed below (`403` otherwise).

## Notes on the contract

- `POST /student/session` reads `code` with a loose schema, not the shared `studentSessionBody`. A malformed code gets the same `invalid_code` response as an unknown one. This is deliberate.
- `ENDPOINTS` in `src/shared/api.ts` lists every route above. Keep it in sync when routes change.
